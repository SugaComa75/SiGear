# Maintainer Guide
** Roles, Responsibilities, and Workflow

## Overview
Maintainers are the stewards of this project.
Their role is to ensure that contributions are reviewed fairly, decisions are transparent, and the project remains aligned with its core principles:
- Open source
- Auditability
- Safety by design
- Ethical development
- AGPLv3 compliance
This guide explains how maintainers operate so that the project remains consistent, trustworthy, and community‑driven.

## Maintainer Responsibilities

Maintainers are expected to:
1. Review Pull Requests
- Ensure contributions follow the AGPLv3 licence
- Check that behaviour is documented and auditable
- Verify that changes align with safety and transparency principles
- Request improvements where needed
- Merge only when the contribution is complete and clear

2. Manage Issues
- Label issues appropriately
- Encourage discussion
- Close resolved or inactive issues
- Redirect non‑security issues to the correct channels

3. Enforce the Code of Conduct
- Address inappropriate behaviour
- Keep discussions respectful and productive
- Protect contributors from harassment or hostility

4. Respond to Security Reports
- Follow the process in SECURITY.md
- Coordinate fixes
- Publish advisories when appropriate

5. Maintain Transparency
- Document decisions
- Avoid private decision‑making
- Ensure rationale is visible to the community

## Decision‑Making Workflow

1. Small Changes
- Minor documentation updates
- Non‑controversial fixes
- Cosmetic improvements
→ Maintainers may approve and merge directly.

2. Significant Changes
- Architectural updates
- New features
- Changes to safety‑critical behaviour
- Modifications to governance
→ Require:
- A GitHub Issue
- Community discussion
- Maintainer consensus
- A documented decision summary

## Safety‑Critical Changes

1. Anything affecting:
- privacy
- data flow
- user protection
- auditability
→ Must include:
- a safety review
- a transparency impact statement
- clear documentation

2. Conflict Resolution
If disagreements arise:
- Discuss respectfully
- Seek consensus
- If unresolved, maintainers make a final decision based on:
- safety
- transparency
- alignment with project goals

## Adding New Maintainers

1. New maintainers may be invited based on:
- consistent, high‑quality contributions
- alignment with project values
- respectful communication
- demonstrated understanding of safety and transparency principles

## Updating This Guide

1. Changes to this document require:
- a public proposal
- community discussion
- maintainer approval
