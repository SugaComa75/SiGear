# Project Governance

** Project Governance & Decision‑Making Model

This document describes how the open‑source project is managed.
It ensures transparency, fairness, and accountability in all decisions.

## Governance Principles

The project is guided by:
- Transparency — All decisions are documented and publicly visible
- Openness — Anyone may propose ideas or improvements
- Safety — Contributions must align with privacy, safety, and auditability principles
- Community Ownership — No single entity controls the project’s direction
- AGPL Compliance — All contributions remain open and share‑alike

## Roles

1. Maintainers
Responsible for:
- Reviewing and merging pull requests
- Ensuring contributions meet safety and transparency standards
- Managing releases
- Enforcing the Code of Conduct
- Responding to security reports
Maintainers do not have unilateral control — they act as stewards.

2. Contributors
Anyone who:
- Submits issues
- Improves documentation
- Writes code
- Reviews proposals
- Participates in discussions
Contributors shape the project’s direction through collaboration.

3. Community Members
Anyone who engages with the project by:
- Asking questions
- Providing feedback
- Sharing ideas
All community members are valued participants.

## Decision‑Making Process

1. Small Changes
Documentation fixes, minor improvements, and non‑controversial updates are approved by maintainers.

2. Significant Changes
Architecture changes, new features, or governance updates require:
- A GitHub Issue describing the proposal
- Community discussion
- A clear summary of the decision
- Maintainer approval

3. Safety‑Critical Changes
Anything affecting:
- privacy
- data handling
- auditability
- system behaviour
…must include:
- a documented rationale
- a safety review
- a transparency impact assessment

## Transparency Requirements
All decisions must be:
- Discussed publicly (Issues or Discussions)
- Documented clearly
- Linked to relevant pull requests
No private decision‑making is allowed for project direction.

## Conflict Resolution
If disagreements arise:
- Discuss openly and respectfully
- Seek consensus
- If unresolved, maintainers make a final decision based on:
- safety
- transparency
- alignment with project goals

## Governance Changes
This document may evolve.
Changes require:
- A public proposal
- Community discussion
- Maintainer approval

## Community Commitment
By participating in this project, you agree to uphold:
- The Code of Conduct
- The AGPLv3 licence
- The principles of transparency, safety, and open collaboration
Together, we build a trustworthy, auditable, and community‑owned system.
