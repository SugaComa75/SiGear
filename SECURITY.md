# Security Policy 

* Project‑Level Security Policy
* This document describes how to responsibly report security‑related issues in the project, not the deployed product or system.
* Because this is an open‑source, safety‑critical initiative, we take security, transparency, and responsible disclosure seriously.

## What Counts as a Security Issue
Please report:
- Vulnerabilities in code, prototypes, or documentation
- Issues that could cause unintended behaviour
- Flaws that undermine transparency or auditability
- Broken or unsafe dependency usage
- Build or configuration weaknesses
- Documentation errors that could mislead contributors or auditors

## What Is Not a Security Issue
Please do not report:
- Product‑level safety concerns (these belong in the system’s governance docs)
- Feature requests
- Concept disagreements
- Typos or formatting issues
- Questions about the AGPL licence
These should be submitted as regular GitHub Issues.

## Reporting a Vulnerability
To report a security issue:
- Do not open a public GitHub Issue.
This protects the community until the issue is understood.
- Contact the maintainers privately using the communication method listed in the repository (email or secure channel).
- Provide:
- A clear description of the issue
- Steps to reproduce
- Potential impact
- Suggested fixes (if known)
We will acknowledge receipt within 72 hours.

##️ Maintainer Response Process
Once a report is received:
- The maintainers will investigate promptly
- A fix or mitigation plan will be prepared
- Contributors may be contacted for clarification
- Once resolved, a public advisory will be published (if appropriate)
We aim to resolve security issues within 14 days, depending on severity.

## Responsible Disclosure
We ask that reporters:
- Do not publicly disclose vulnerabilities before a fix is available
- Act in good faith
- Avoid accessing or modifying data beyond what is necessary to demonstrate the issue
This ensures the safety and trust of the entire community.

## Commitment to Transparency
This project exists to be open, auditable, and trustworthy.
We will always handle security issues with honesty, clarity, and respect for contributors and users.
